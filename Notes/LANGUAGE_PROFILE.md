# Notes/LANGUAGE_PROFILE.md

本文件规定正式 Notes 的默认中文教材语体。来源原文、代码和约定名称可按任务另行覆盖。

## 1. 基本语体

- 主语言：简体中文。
- 语气：准确、连续、解释性；避免词典条目、审查报告和中英混合速记。
- 句子优先说明具体对象、关系和动作，不用流程词替代数学内容。
- 第一句优先建立一个稳定对象，不同时处理术语多义、历史、边界和下游用途。
- 不为满足“立即解释”而把类别、定义、条件和边界全部塞进一个长句；相邻句只要在首次依赖前完成闭合即可。

## 2. 英文与缩写

- 公认缩写可保留：CSS、HGP、qLDPC、LP、POVM 等。
- 首次出现时优先写中文术语，必要时括注英文全称与缩写。
- 不在中文正文反复混用 `check matrix`、`row pair`、`support space` 等英文短语。
- 来源原句、代码标识和必须保持的作者术语除外。

## 4. 定义语句

避免循环或空泛表达。合格局部定义至少提供类别、数据、作用、区分中的两项。

定义闭合的目标是让读者在首次依赖前能够继续推理，不是追求同一句承载全部信息。优先使用短而连续的两三句，而不是破折号或多层括号堆叠。

## 5. 主线与补充

- 主线句子回答当前问题；
- optional detail 应有明确标题或 callout，并能被跳过；
- 补充块结束后用一句话回到主问题；
- 不让完整局部计算长期占据主语位置，使读者忘记当前对象。

## 6. 标题

标题使用对象短语、问题短语或构造短语。Optional detail 的标题应明确其可跳过性质，例如“补充推导：……”或 Obsidian details callout。

## 7. 自然度检查

清稿时检查：

- 是否出现不必要的“既指 A，也指 B”；
- 是否按 checklist 一项一句机械展开；
- 是否中英混合；
- 是否用空泛替代词避免具体解释；
- 是否因 closure rule 形成过长首句；
- 是否把辅助推导写得比当前主对象更醒目；
- 是否有正确但不能继续使用的句子。
