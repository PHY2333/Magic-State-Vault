# Notes/WORKFLOWS/pedagogy-patterns.md

Didactic Architect 选择模式；Writer 不把模式名称写入正文。

## 1. 类别定位 → 基本数据 → 构造

适合第一次引入对象、构造或码族。

```text
它是什么 → 由什么给出 → 当前要构造什么 → 怎样开始
```

## 2. 问题 → 障碍 → 工具 → 解决 → 作用

适合新工具的意义依赖已经出现的问题。工具名称不能早于问题，除非明确采用 whole-first 预览。

## 3. 整体 → 部件 → 重新组装

适合多部分强耦合、局部意义依赖整体的对象。

```text
简化整体 → 标出部件 → 分别解释 → 重新组装
```

整体预览中的标签若只用于定位，必须说明不要求立即操作。

## 4. 结果 → 证明地图 → 局部推导 → 汇总

适合长证明和复杂推导。证明地图必须说明每一步完成什么，不只是目录。

## 5. Worked example → 抽象 → 支架渐隐

适合矩阵、指标、算法和符号操作。

## 6. 对比 → 反例 → 正式边界

适合相邻概念和常见混淆。

## 7. 来源任务 → 阅读地图 → 必要补充 → 返回来源

适合 paper-guide 和具体图表。

## 8. Unit phases

一个 unit 可分若干 phase。每个 phase 只承担一个主要认知动作：

- 建立类别；
- 提出问题；
- 给整体位置；
- 引入一个新关系；
- 完成一次计算；
- 汇总并释放工作记忆。

若一个 phase 同时引入多个新对象、多个新关系和大量新符号，应拆 phase 或新 unit。

## 9. Load profile

每个 phase 记录：

- `new_entities`
- `new_relations`
- `new_notation`
- `holding_set`
- `consolidation`

对于 `unseen` 或 `unverified` 的首次教学，若在一次 consolidation 前同时新增超过两类核心关系或超过四个需要操作的新符号，应给出明确理由，否则拆 phase。

## 10. 模式选择

至少回答：

- 目标是识别、构造、计算、证明、比较还是读懂来源；
- 读者 capability facets；
- 局部是否必须先知道整体；
- 是否存在自然障碍；
- 是否需要示范操作；
- 是否存在边界混淆；
- explanation claims 的前提是否适合在当前模式中闭合。
