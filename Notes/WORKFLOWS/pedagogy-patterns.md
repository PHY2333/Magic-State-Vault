# Notes/WORKFLOWS/pedagogy-patterns.md

Didactic Architect 选择模式；Writer 不把模式名称写入正文。

## 1. 常用模式

1. 类别定位 → 基本数据 → 构造
2. 问题 → 障碍 → 工具 → 解决 → 作用
3. 整体 → 部件 → 重新组装
4. 结果 → 证明地图 → 局部推导 → 汇总
5. Worked example → 抽象 → 支架渐隐
6. 对比 → 反例 → 正式边界
7. 来源任务 → 阅读地图 → 必要补充 → 返回来源

## 2. Unit phases

一个 phase 只承担一个主要认知动作。若同时引入多个对象、关系和大量符号，应拆 phase 或把支持性细节移入 optional block。

## 3. Load profile

记录 `new_entities / new_relations / new_notation / holding_set / consolidation`。

## 4. Mainline 与 detail

每种模式都要说明：

- 主问题何时出现；
- 支持性细节何时结束；
- 如何回到主结论；
- 哪些步骤是 core，哪些可 optional/upstream；
- 是否存在过长 latency。

长证明采用 proof map；worked example 的局部计算若不是出口能力，可放 optional detail；整体图中的定位标签不要求立即操作。

## 5. 模式选择

回答目标动作、learner facets、整体与局部关系、自然障碍、示范需求、边界混淆、claim premises，以及 explanation depth 与主线成本。
