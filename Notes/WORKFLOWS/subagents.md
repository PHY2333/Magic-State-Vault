# Notes/WORKFLOWS/subagents.md

本文件只规定复杂笔记任务中的只读检查。正文流程见 `note-writing.md`，执行责任属于主 Executor。

## 1. 使用原则

- subagent 只检查，不写正文，不修改文件，不创建或批准计划。
- 所有结论必须给出文件、标题、公式或具体段落证据。
- subagent 不重新设计教学主线；发现主线问题时标记为 semantic issue，交还 Planner 或用户。
- 改错字、修链接、移动文件和短小局部修改通常不需要 subagent。

复杂重写、长推导、论文转写、合并拆分或用户指出质量问题时，至少在草稿完成后调用必要检查。

## 2. 共同输出格式

```md
## <检查名称>

### 已读依据

- 文件：
  - 采用内容：

### 发现

1. 严重程度：blocker | major | minor
   - 位置：
   - 问题：
   - 证据：
   - 影响：
   - 建议修复：

### 结论

- pass | changes_required | blocked：
- 必须处理：
```

只写“通过”“表达清楚”或“建议补充”视为无效。

## 3. 检查角色

### 3.1 仓库一致性检查

检查：

- canonical ownership 是否正确；
- 是否重复已有定义、证明或例子；
- 上下游链接和文件路径是否有效；
- 新建、移动或拆分是否需要更新 `Notes/00-index.md`；
- canonical 归属、别名或来源关系是否需要更新 `CANONICAL_KNOWLEDGE.md`；
- 正式笔记是否引用了 `WORKING` 中间产物。

不得重新规划正文主线。

### 3.2 数学与来源检查

检查：

- 定义、公式链和关键中间步骤；
- degree、sign、index、domain/codomain 与左右作用；
- 条件在何处使用；
- 一般情形与特殊系数情形是否混淆；
- 论文、教材或翻译的页码、定理号、公式号和约定是否被准确采用；
- 计划中的数学承诺是否真正完成。

来源不足时必须明确指出，不得用模型常识补齐为已核对事实。

### 3.3 正文与格式检查

只依据 `Notes/WRITING_GUIDE.md` 检查：

- 主线和依赖顺序；
- 术语、条件、映射和推导是否写清；
- 是否残留问答、任务、计划、验收或工具语言；
- 标题、例子和边界声明是否合适；
- 是否残留旧解释、重复背景、临时编号或不可追踪引用。

不得另行发明文体规则。

## 4. 主 Executor 的处理方式

- `minor`：直接修复。
- `major`：修复后重新调用相关检查。
- `blocker`：停止交付，写入 `REVIEW.md`，返回对应角色。

主 Executor 只汇总结论和处理结果，不把 subagent 的完整检查稿写入正式笔记。
