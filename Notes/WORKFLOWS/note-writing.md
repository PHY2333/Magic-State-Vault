# Notes/WORKFLOWS/note-writing.md

本文件规定复杂笔记写作的主流程。写作判断见 `Notes/WRITING_GUIDE.md`；subagent 调用见 `Notes/WORKFLOWS/subagents.md`。

---

## 0. 适用范围

用于：新增笔记、重写旧笔记、整理长推导、论文转写、合并拆分、调整学习路径。

不用于：改错字、修链接、移动文件、纯格式化、用户明确要求的短小局部修改。

---

## 0.1 中间产物存放

写作蓝图、教案、验收稿等中间产物不属于正式知识库正文，不得散落在 `Notes/` 的正式主题目录，也不得放入 `Notes/WORKFLOWS/`。

默认策略：

```md
默认：只在对话里输出教案和写作蓝图，不落盘。
复杂重写：用户明确允许后，保存到 `Notes/WORKING/note-plans/`。
正文完成：可删除 plan，或保留作为写作记录。
```

若用户允许保存中间产物，使用：

```md
Notes/WORKING/note-plans/<笔记名>.plan.md
```

`Notes/WORKING/note-plans/` 只保存某篇笔记的工作产物，不保存通用流程规则。通用规则仍写入 `Notes/WORKFLOWS/`。

---

## 1. 阅读包

先读取：

1. `AGENTS.md`
2. `Notes/WRITING_GUIDE.md`
3. `CANONICAL_KNOWLEDGE.md`
4. 当前笔记
5. 相关上游笔记
6. 相关下游笔记

输出阅读包，不写正文。

阅读包必须说明：

```md
## 阅读包

### 当前笔记
- 文件：
- 当前问题：
- 本次目标：

### 上游笔记
- 文件：
  - 继承内容：
  - 本文承接方式：
  - 不重复展开：

### 下游笔记
- 文件：
  - 下游调用内容：
  - 本文边界：

### 缺失素材
- 缺少的例子：
- 缺少的来源：
- 待核对约定：
```

若阅读包没有具体继承内容，停止。

---

## 2. 资料研究判断

本地素材不足时，启动资料研究。需要启动的情况：

- 缺标准例子、来源、符号约定或命名来源；
- 上游概念笔记缺操作直觉；
- 准备用自造例子代替标准例子；
- 理解验收或例子验收不通过；
- 用户指出“不显然”“为什么是这个结构”“缺素材”。

资料研究只补素材，不写正文。

输出：

```md
## 资料研究
- 是否启动：
- 理由：
- 来源：
  1. 来源：
     - 采用内容：
     - 用途：
     - 待核对：
- 对主线的影响：
```

“教材/讲义类型知识”“常识上可知”但不给具体来源，视为不通过。

---

## 3. 学习路径

学习路径不是目录。每一步必须说明读者为什么需要它。

输出：

```md
## 学习路径草案

### 第 1 步：...
- 读者已有知识：
- 本步新增内容：
- 解决的理解障碍：
- 删除本步会导致：
- 下一步如何使用：
- 是否需要素材：
```

若某一步只能写成“给出定义 / 说明相容 / 推出结论”，继续细化。

---

## 4. 验收

正文写作前至少完成三类验收。

### 4.1 理解验收

检查读者是否能沿路径读下去。

```md
## 理解验收

### 卡点
1. 卡点：
   - 读者缺少什么：
   - 后文哪里会断：
   - 处理方式：重写 / 加例子 / 补前置 / 查资料 / 删除

### 结论
- 通过 / 不通过：
- 必须修改：
```

### 4.2 例子验收

需要例子时，检查例子是否真的解决理解障碍。

```md
## 例子验收
- 是否需要例子：
- 具体对象：
- 操作过程：
- 解决的困难：
- 如何回到正式定义：
- 不承担什么：
- 通过 / 不通过：
```

例子不能只证明“存在一个同类型对象”。上游概念笔记优先使用标准例子或典型模型。

### 4.3 推导验收

涉及公式、条件或结论时，检查推导链。

```md
## 推导验收
- 上游公式或定义：
- 本文目标：
- 中间步骤：
- 关键条件的作用：
- 待核对点：
- 通过 / 不通过：
```

禁止用类型签名、定义域和值域代替推导。

---

## 5. Subagent 检查

复杂笔记、长推导、论文导读或用户指出质量问题时，按 `Notes/WORKFLOWS/subagents.md` 调用只读 subagent。

主流程只记录 subagent 结论：

```md
## Subagent 检查摘要
- 路径检查：通过 / 不通过；证据：
- 理解检查：通过 / 不通过；证据：
- 推导检查：通过 / 不通过；证据：
- 素材检查：通过 / 不通过；证据：
- 文体检查：通过 / 不通过；证据：
- 必须修改：
```

任一必需检查不通过，返回对应阶段。

---

## 6. 修订后的学习路径

汇总阅读包、资料研究、验收和 subagent 结果，输出最终主线。

```md
## 修订后的学习路径

### 第 1 步：...
- 读者已有知识：
- 本步新增内容：
- 解决的理解障碍：
- 下一步如何使用：

## 本次写作范围
- 写入当前笔记：
- 拆出或补充前置：
- 只建立链接：
- 不在本文展开：
- 待核对：
```

---

## 7. 写作蓝图

验收通过后，不要直接写正文。先写蓝图，把验收表转成自然正文结构。

```md
## 写作蓝图

### 正文主线
用 3 到 6 句话说明正文从哪里开始，经过哪些对象，最后停在哪里。

### 章节安排
#### 标题：...
- 本节处理的具体数学对象：
- 从上一节如何过渡：
- 本节需要铺垫什么：
- 本节结束时读者应得到什么：
- 不应直接写入的验收语言：

### 例子安排
- 例子出现位置：
- 例子前需要铺垫：
- 例子只说明：
- 例子不承担：

### 推导安排
- 必须完整写：
- 只说明理由：
- 只外链：

### 标题检查
- 标题是否为主题短语：是 / 否
- 是否有完整判断句标题：有 / 无

### 验收语言过滤
- 是否残留“本文只处理”“本文不”“为了看清”“解决的理解障碍”“输入/输出”等验收语言：有 / 无
- 替换方案：
```

蓝图通过后才能写正文草稿。

若用户允许保存中间产物，写作蓝图保存到 `Notes/WORKING/note-plans/<笔记名>.plan.md`。未获允许时，只在对话中输出，不创建文件。蓝图不得散落在正式主题目录，也不得放入 `Notes/WORKFLOWS/`。

---

## 8. 正文草稿

正文只能依据写作蓝图写，不直接搬运验收表。

要求：

- 不写成问答；
- 不把用户问题直接写成段落；
- 不用标题提前塞结论；
- 不用类型签名代替解释；
- 不用例子代替正式定义；
- 不把边界说明放在读者还不需要的位置。

若写作时发现主线仍不通，停止并返回蓝图。

---

## 9. 语言清稿

正文草稿完成后，必须做一次语言清稿。语言清稿只改表达，不改变数学主线。

检查：

- 验收语言、教案语言或任务说明是否进入正文；
- 是否过早声明下游边界；
- 是否用“输入/输出/角色/结构/层面/视角”等元语言替代具体数学对象；
- 标题是否是完整判断句；
- 例子前是否默认读者尚未具备的背景。

输出：

```md
## 语言清稿
- 需要修改：
  1. 原句：
     - 问题：
     - 修改后：
- 可以保留：
  - 句子：
    - 理由：
- 通过 / 不通过：
```

若语言清稿不通过，回到正文草稿阶段修改；不得写入正式文件。

---

## 10. 清稿与交付

正文完成后按 `Notes/WRITING_GUIDE.md` 做最终清稿。

最终交付说明：

- 修改文件；
- 主线如何改善；
- 是否新增前置；
- 是否更新 `CANONICAL_KNOWLEDGE.md` 或 `Notes/00-index.md`；
- 是否创建、保留或删除了 `Notes/WORKING/note-plans/` 中间稿；
- 是否仍有 `待核对`、`TODO：补引用` 或 `待补推导`。

正式笔记和交付中不得保留工具痕迹、临时检索编号、内部 line id 或不可追踪引用格式。
