# Notes/OBSIDIAN_MATH.md

目标渲染器是 Obsidian / MathJax。本文件既规定目标格式，也规定 Codex 对格式错误的处理权限。

## 1. 目标格式

行内公式：

```md
矩阵满足 $H_XH_Z^T=0$。
```

块公式：

```md
$$
C_2 \xrightarrow{H_Z^T} C_1 \xrightarrow{H_X} C_0
$$
```

两个 `$$` 必须各自单独成行。

## 2. 不应保留的形式

```text
\(...\)
\[...\]
/(...)
/[...]
$$ equation $$
```

不得把需要渲染的公式留在反引号代码中；不得把整份 Markdown 作为 JSON 字符串写入文件。

## 3. Codex 直接修复原则

格式问题由 Codex读取上下文后直接修复，不使用规则式自动 fixer，也不因纯格式问题返回 Pro。

判断标准不是“字节是否完全相同”，而是：修复前后表达的是不是同一个数学陈述，且意图是否能由当前段落、相邻公式或已读取来源唯一确定。

### A. Markdown / Obsidian 外层格式

Codex直接修复，例如：

- 把 TeX 风格行内分隔符改为 `$...$`；
- 把 TeX 风格块分隔符改为独立的 `$$` 块；
- 把误写的斜杠数学分隔符改为正确分隔符；
- 把 `$$ equation $$` 拆成独立块公式；
- 补齐块公式周围的换行和空行；
- 补齐 callout 内块公式每行需要的 `>`；
- 移除明显误加在数学公式外层的代码格式；
- 修复 Markdown 表格、引用或缩进导致的纯渲染问题；
- 调整中文标点与公式边界，但不改变句子含义。

### B. 可唯一判断的 LaTeX 语法或转义

Codex可以直接修复，例如：

- Browser 或字符串序列化造成的重复反斜杠；
- 明显缺失或多余、且只有一种合理闭合方式的花括号；
- 明显的 LaTeX 环境、矩阵换行或命令拼写格式错误；
- 同一公式在正文与来源中已有唯一正确写法的转义问题。

这类修复必须以当前数学语境或已读取来源为依据，不能靠猜测。

### C. 不属于格式修复

以下问题不得由 Codex借“格式修复”静默改变：

- 变量、运算、指标、上下标、正负号、转置或共轭；
- 等号、包含关系、映射方向或量词；
- 定义域、陪域、条件和结论；
- 公式项的增删或重排；
- 正文的数学解释、证明步骤和教学顺序；
- 存在两个以上合理解释的未配对分隔符或括号；
- 正文与公式冲突；
- 来源之间冲突。

这些情况返回 Pro 或来源核验。

## 4. Codex 修复检查

Codex修复时应按以下顺序：

1. 读取错误所在的完整段落，而不是只看 checker 行号；
2. 必要时读取相邻公式或 request 指定来源；
3. 判断是 A、B 还是 C 类；
4. A、B 类直接编辑；
5. 复读修复前后内容，确认数学陈述和正文含义不变；
6. 重新运行 checker；
7. 在 `APPLY_REPORT.md` 中写一条简洁摘要。

不要求生成逐字符证明、公式 payload hash 或单独审查文件。Git diff 已经保存精确变更。

## 5. 表格与 callout

表格中只使用短行内公式。复杂公式移到表格外。

Callout 中块公式的每一行都保留 `>`：

```md
> [!note]- 补充推导
>
> $$
> XZ=-ZX
> $$
```

## 6. Checker 的地位

```bash
python Notes/TOOLS/check_obsidian_math.py <file-or-directory>
```

Checker 是诊断工具，只负责定位常见 delimiter 和 Markdown 结构问题；它不是修复器，也不能替代 Codex 对数学上下文的判断。

Reader-visible 文件在最终提交前必须通过 checker。若 Codex按本文件修复后仍不能通过，或修复可能改变数学含义，才停止并返回 Pro。
